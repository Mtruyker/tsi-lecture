# Лекция 15. Ethernet, TCP/IP и сетевые службы

## Цели

Понимать уровневую модель, работу коммутатора и маршрутизатора, адресацию IPv4/IPv6 и базовые службы сети.

## 1. Уровни

Уровневая модель разделяет функции: физическая передача, кадры локальной сети, пакеты между сетями, транспорт и приложения. OSI полезна как учебная схема, TCP/IP — как реально применяемый стек. Инкапсуляция добавляет заголовки, принимающая сторона удаляет их.

## 2. Ethernet

Коммутатор изучает MAC-адреса источников и пересылает кадры на нужный порт. Broadcast распространяется в пределах VLAN. VLAN логически разделяет сеть, но межсетевое взаимодействие требует маршрутизации и правил доступа.

Скорость порта не равна полезной скорости приложения: учитываются заголовки, задержка, ошибки, возможности конечных устройств и совместное использование uplink.

## 3. IP

IPv4 адрес состоит из сетевой и узловой частей по префиксу. Частные адреса обычно выходят в Интернет через NAT. IPv6 имеет большее адресное пространство и использует иной набор механизмов; NAT не является основой безопасности ни для IPv4, ни для IPv6.

Маршрутизатор выбирает следующий переход по таблице маршрутов. Default gateway используется, когда адрес назначения вне локального префикса.

## 4. Транспорт

TCP обеспечивает упорядоченный надёжный поток, управление перегрузкой и повторную передачу. UDP даёт датаграммы без гарантии доставки; надёжность при необходимости реализует приложение. QUIC работает поверх UDP и объединяет защищённый транспорт с современными механизмами управления потоками.

## 5. Службы

DHCP выдаёт параметры сети; DNS сопоставляет имена и данные; NTP синхронизирует время; directory/identity управляет учётными записями. Ошибка DNS часто выглядит как «Интернет не работает», хотя IP-связность сохранена.

## 6. Проект малой сети

Интернет → межсетевой экран/маршрутизатор → управляемый коммутатор → рабочие места, сервер/NAS, точки доступа и МФУ. Пользовательские, гостевые, управляющие и IoT-устройства целесообразно разделить VLAN и правилами.

## 7. Диагностика

Проверять снизу вверх: питание/линк → адрес и префикс → gateway → локальный ping → удалённый IP → DNS → порт приложения. Ping не доказывает исправность веб-сервиса, а отсутствие ответа ping не всегда доказывает разрыв.

## 8. Подсети IPv4

Префикс /24 оставляет 8 бит узловой части. Традиционно сеть и broadcast не назначаются хостам. При делении на /26 получают четыре диапазона по 64 адреса, обычно 62 пригодны для узлов. План должен оставлять рост и отделять функции.

## 9. IPv6

IPv6 использует 128-битные адреса и префиксы, Neighbor Discovery вместо ARP, SLAAC и/или DHCPv6. Link-local адрес существует на интерфейсе независимо от глобального. Правила firewall нужны явно: отсутствие NAT не означает отсутствие защиты.

## 10. ARP и коммутация

Перед отправкой IPv4-пакета соседу узел узнаёт его MAC через ARP. Для удалённого адреса запрашивается MAC шлюза, а IP назначения не меняется. Коммутатор пересылает кадр, маршрутизатор создаёт новый кадр для следующего сегмента.

## 11. TCP подробнее

Трёхэтапное рукопожатие синхронизирует соединение. Номера последовательности и подтверждения обеспечивают порядок. Потери вызывают повтор, congestion control регулирует отправку. Большая пропускная способность при высокой RTT требует достаточного окна.

## 12. DNS

Рекурсивный resolver получает ответ через иерархию и кэширует по TTL. Записи A/AAAA указывают адрес, CNAME — псевдоним, MX — почтовый маршрут. Изменение DNS распространяется не мгновенно из-за кэшей.

## Развёрнутый пример прохождения пакета

ПК 192.168.10.20/24 обращается к серверу 192.168.20.30. Он видит, что адрес вне локальной сети, через ARP узнаёт MAC gateway и отправляет кадр маршрутизатору. Маршрутизатор уменьшает TTL, выбирает маршрут и создаёт новый кадр во VLAN сервера. IP назначения остаётся серверным, если нет NAT.

При отказе сначала проверяют адрес/префикс, затем gateway, маршрут, ACL и службу. Если ping проходит, но TCP-порт закрыт, физическая и IP-связность недостаточны для вывода об исправности приложения.
